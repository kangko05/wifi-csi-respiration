# 프로젝트 작업 지침

> 이 지침은 `python/` 폴더(Python 탐색·수집·검증 프로젝트)의 지침이다. 원본 데이터는 저장소 루트의 `../data/`, 펌웨어는 `../csi-rx/`·`../csi-tx/`에 있다. 이 문서에서 `data/`, `csi-rx/`, `csi-tx/`는 이 위치들을 뜻한다.

## 목표와 현재 단계

- ESP32-C5 TX/RX로 방 안의 호흡을 관측하고 호흡 주기를 추정하는 것이 장기 목표다. 먼저 새 데이터의 품질과 호흡 변화의 관측 가능성을 확인한다. 멂(기존 기준 90–100cm)의 약한 호흡 성분이 주요 관심사다.
- 이 프로젝트는 `../../wifi-csi-proto`의 후속 탐색 공간이다. 레거시 전체를 복제하거나 기존 전처리·판정 기준을 정답으로 고정하지 않는다.
- 2026-09-16 사용자 결정: 새 측정과 데이터를 보며 접근법을 다시 검토한다. 진폭·위상/복소 CSI·CIR 중 메인 경로는 아직 확정하지 않았다. 평균·필터·ACF·게인 보정도 검토 후보이며 일괄 구현 승인이 아니다.
- 첫 출발 후보는 실제 TX 출력 설정 확인과 기준 측정이다. 수집 길이·반복·거리·출력 비교값은 아직 미정이다. 현재 단계는 펌웨어 소스를 저장소로 들여오고 문서를 정리한 상태이며, 사용자가 기본 출력 설정 그대로 TX·RX 플래시를 완료했다고 보고했다. 출력 비교는 나중으로 미뤘다. 2026-09-16 옆 교수회의실에서 21개 세션을 수집했다(`PROGRESS.md`). 포트 열기·수집·플래시·설정 변경은 여전히 해당 실행 요청과 준비 확인 뒤에만 수행한다.
- 측정 장소는 **옆 교수회의실**로 확정됐다(2026-09-16 사용자 결정). 다시 묻지 않는다.
- 원본 수집기 `collect_legacy.py`(작성 당시 `collect.py`)와 오프라인 테스트가 준비됐고 2026-09-16 이 환경에서 검증했다(`.venv`·`pyserial==3.5`, 테스트 41개 통과, `--help` 실행). 사용법·보존 계약은 `docs/data-collection.md`에 있다. 수집기는 지정한 포트 하나만 열고 미확인 조건을 unknown으로 기록한다.
- 2026-09-17 사용자 결정: 신호처리는 최종적으로 **RX ESP32-C5 온디바이스 C**로 포팅한다. 빌드는 ESP-IDF(CMake)에 맞춘다. 신호처리 코드는 송수신 펌웨어와 분리하고, 기존 Python은 지우지 않고 이 `python/` 폴더를 독립 Python 프로젝트 루트로 삼아 수집·대조·검증용으로 둔다. Python 코드를 정리하거나 리팩터링하는 데 시간을 쓰지 않는다.
- 옆 교수회의실 수집은 **사용자가 이미 요청했다.** 이를 위해 새 승인을 다시 받을 필요는 없다. 다만 실행은 미확인 조건(수집 길이·재실·거리·자세·현장 준비 상태)이 정해지고 준비가 확인될 때까지 기다린다. 포트 열기·플래시·설정 변경은 여전히 해당 실행 시점의 준비 확인 뒤에 한다.

- 한 번의 명확한 작업 지시에 구현·필요한 테스트·문서화를 묶는다. 불필요한 다중 에이전트 운용은 피한다.
- Claude에 이 파일과 승인 범위, 변경 가능 경로, 보존 규칙, 원본 데이터/수동 기준 분리, 커밋·푸시 금지를 명시적으로 전달한다. Claude CLI의 `--safe-mode` 지원 여부를 확인하고 사용하여 CLAUDE.md·사용자 정의 hooks 등의 자동 로드를 막는다. 권한 검사 우회 옵션은 사용하지 않는다.

- CLI 실행·로그인·권한 문제로 위임할 수 없으면 원인을 짧게 알린다. 큰 구현을 말없이 Codex 직접 작업으로 전환하지 않는다. 작은 지침 수정 등 관리 작업은 직접 할 수 있다.
- 위임은 권한 우회·범위 확대 승인이 아니다. 다른 프로젝트나 참조 원본에 쓰지 않는다. 커밋·푸시는 별도 명시 요청이 있을 때만 한다.

## 현재 장비 상태 — 사용자 설명, 2026-09-16

- TX와 RX는 ESP32-C5이며 같은 케이스 안에 있다. 2026-09-16 새 케이스를 받았고(수령 확인) 장착 여부·재질·장착 후 안테나 간격은 미확인이다. 같은 날 사용자가 기본 설정으로 TX·RX 플래시를 완료했다고 보고했다. 현재 상태 정리는 `docs/hardware-status.md`에 있다.
- 사용자 지정 포트는 **RX COM3, TX COM4**다. 연결 상태는 바뀔 수 있으므로 실제 측정 전에 다시 확인한다. 자동 포트 검색만으로 역할을 재지정하지 않는다.
- 실제 TX 출력값은 미확인이다. 과거 삭제된 8dBm 기록의 값을 현재 설정으로 사용하지 않는다.
- 케이스 내부 안테나 간격, 현재 채널·대역폭·수집률·펌웨어 버전도 새 실험 기준값으로 검증되지 않았다. 실제 설정과 확인 근거를 기록한다.
- TX/RX 하드웨어와 안테나 배치는 기준 측정에서 유지한다. 출력·배치·케이스 비교는 승인된 범위에서 한 요인씩 바꾸고 변경점을 기록한다. 포트를 열기·수집·플래시·출력 변경은 해당 실행 요청과 준비 상태를 확인한 뒤 수행한다.

## 데이터와 평가 계약

- 수집 원본을 덮어쓰거나 삭제하지 않는다. 세션별 새 ID를 사용하고 원본과 파생 결과를 분리한다. 중단·오류 수집도 상태와 함께 보존한다.
- 실제 타임스탬프, 원본 행·열 인덱스, I/Q 순서와 signed 해석, 메타데이터 정렬, 유효성 마스크를 유지한다. 긴 공백을 조용히 메우거나 시간을 압축하지 않는다.
- 보간·재표본화·필터 경계 제외는 설정과 실제 시간 지지를 기록한다. 무효값을 유효한 0으로 대체하지 않는다.
- 수동 호흡 횟수와 외부 기준은 추정 후 평가에만 사용한다. 열·주파수·필터·후보 선택에 정답을 사용하지 않는다. 전체 기록 횟수를 부분 구간 정답으로 간주하지 않는다.
- 빈 방은 0bpm 회귀 정답이 아니다. 사람 있음·불확실 횟수·움직임·빈 방을 구분하고 동기화 여부를 기록한다.
- 합성 테스트는 계산과 보존 계약을 검증하며 실제 호흡 정확도를 입증하지 않는다. 원본 데이터 변경이 없음을 필요한 해시/메타데이터 검사로 확인한다.
- 탐색 데이터와 최종 평가 데이터를 분리한다. 같은 데이터에서 설정을 반복 선택한 결과를 독립 검증이라고 하지 않는다.

## 신호처리 해석과 비교

- 강한 직접 경로가 약한 호흡을 가린다는 설명은 가설이다. 정적 성분, 곱셈형 게인 오차, 랜덤 잡음을 구분한다. 정적 평균 제거를 직접 경로만의 제거나 RF/ADC 포화 복원으로 설명하지 않는다.
- 잡음 전체가 독립·평균 0의 가우시안이라고 가정하지 않는다. 평균/필터 후 매끈한 파형이나 ACF 피크만으로 호흡 검출을 주장하지 않는다.
- CIR은 복소 CSI를 지연 영역으로 표현한 것이며 자체적으로 진폭과 위상을 갖는다. IFFT 축·서브캐리어 배열·누락 bin·대역폭을 검증하고 tap을 곧바로 물리 거리나 특정 반사 경로로 해석하지 않는다.
- 진폭·위상·CIR은 같은 원본을 공유한다. 각 경로를 비교할 때 후보와 confidence를 서로의 결과로 만들지 않는다. 일치가 독립된 호흡 증명은 아니다.
- 한 번에 한 요인을 바꾸고 원본 기준선을 포함한다. 실행 전 가설·설정·분석 구간·평가 항목·중단 기준을 기록한다. 설정 변경 후 실행은 새 ID로 남긴다.
- 멂 그룹이 있으면 보고에서 먼저 다루고 전체·기타 거리군을 이어서 제시한다. 진단 피크, 채택, 채택 중 오류를 분리한다. 고정 ±1.1/±2.2bpm와 실제 관측 길이의 해상도를 구분한다.
- 기존 기준선을 재사용하면 집중도0.35·국소 SNR3을 그대로 유지한다. 낮은 채택 수를 이유로 낮추지 않는다. 새로운 방식의 기준은 별도 설정용 데이터와 평가 계획을 마련하며 기존25개에 맞춰 조정하지 않는다.
- 약한 근거는 불확실로 보고하고 실패 결과도 보존한다.

## 구현이 시작될 때

- 처리 코드와 수집·보고 코드를 분리하고 설정을 명시적으로 전달한다. 가능하면 결과 배열을 읽기 전용으로 유지한다.
- Python 환경·의존성·실행 명령은 `docs/data-collection.md`에 정리했고 `PROJECT.md`에는 실제 검증된 명령만 옮긴다. `.venv` 생성·`pyserial==3.5` 설치·`unittest discover -s tests` 실행은 2026-09-16에 검증됐다(41개 통과). 2026-09-17 `python/`으로 옮긴 뒤에도 이 폴더에서 `unittest discover -s tests`로 실행한다(`.venv`는 `python/.venv`로 새로 만들었다). 분석기는 없고 하드웨어 동작은 검증되지 않았다.
- 테스트는 I/Q 해석, 시간/메타데이터 정렬, 마스크, 경계/공백, 중단과 원본 보존 등 의미 있는 계약에 집중한다.
