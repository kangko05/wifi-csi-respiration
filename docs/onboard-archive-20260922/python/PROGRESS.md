사용자가 신호처리를 RX ESP32-C5 온디바이스 C로 포팅하기로 정했다. 기존 Python은 지우지 않고, 송수신 펌웨어(`csi-rx/`, `csi-tx/`)와 원본 `data/`를 뺀 나머지를 모두 저장소의 `python/` 폴더로 옮겼다. 이 폴더를 독립 Python 프로젝트 루트로 쓴다.

- 옮긴 것: `src/`, `tests/`, `scripts/`, `collect_legacy.py`, `requirements.txt`(git mv), `docs/`, `outputs/`, `references/`, `AGENTS.md`, `PROJECT.md`, `PROGRESS.md`. 저장소 루트에는 `csi-rx/`, `csi-tx/`, `data/`, `README.md`, `.gitignore`만 남았다.
- 삭제한 것: 루트의 `.venv`(사용자 지시에 따라 `python/.venv`로 새로 만들고 `requirements.txt` 설치, pyserial 3.5·numpy 2.5.3), 비어 있던 루트 `.tmp-tests/`.
- 코드: 동작은 바꾸지 않고 경로 계산만 고쳤다. 스크립트 `ROOT`는 `python/`, 원본은 `DATA_ROOT = ROOT.parent / "data"`, 레거시는 `ROOT.parent.parent / "wifi-csi-proto"`를 가리킨다. `verify_sources.py`의 data 키는 이전과 같은 `data/…` 형식을 유지한다. 수집기 `--data-root` 기본값도 저장소 루트 `data/`를 가리킨다.
- `.git/info/exclude`를 새 경로로 바꿨다(`/data/`, `python/...`).
- 확인: `discover -s tests`는 85개가 돌고 14개가 실패한다(작성 중인 `test_preprocessing_to_csidata`만 실패, 이동 전과 동일, skip 0). `scripts/verify_sources.py --check outputs/legacy_run_20260917/sources_before.json`은 data 84개·레거시 44개가 일치해 통과했다. 수집기와 스크립트 5개 모두 `--help`가 정상 동작한다.
- 스크립트 내용이 바뀌었으므로, `outputs/legacy_run_20260917/`에 남은 래퍼 SHA256과 `outputs` 절대 경로는 이동 전 기록이다. 기록은 수정하지 않았다.

## 2026-09-17 클론만으로 실행 가능하게 구성 (레거시 코드 복사, 코드 git 추적)

사용자 요청: 저장소를 git으로 클론하면 이 프로젝트만으로 실행되게 한다.
