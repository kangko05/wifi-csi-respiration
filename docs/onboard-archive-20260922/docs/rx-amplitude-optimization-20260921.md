# RX 진폭 처리 최적화 실험 — 2026-09-21

## 목적과 비교 조건

ESP32-C5 RX(`/dev/ttyUSB0`)에 직접 플래시해 기존 진폭 처리와 다섯 변경을
개별 비교했다. `-O2`, 240 MHz, 8 MiB PSRAM, 40 MHz 설정이다.
하나의 약 60초 원시 윈도우를 받은 다음 CSI 수신을 끄고 같은 입력으로
모든 변형을 실행한다. 마지막에는 기준 처리를 반복한다.
UART의 `fingerprint`는 동일 입력 확인용 FNV-1a 값이다.

이번 실험은 **고정 입력 연산 벤치마크**다. 연속 수신·매초 분석을 완료한
실시간 시스템이나 실제 호흡 정확도 검증을 뜻하지 않는다. 기존 로그의
56.626초와 환경이 완전히 같지는 않으므로 이번 실행의 baseline과 비교한다.

## 적용한 변경

| 이름 | 단독 변경 | 결과 의미 |
| --- | --- | --- |
| `float_fft_fir` | FFT butterfly와 FIR 누산을 float로 변경 | PSD/ACF 점수 계산 등은 여전히 double. 양자화 아님 |
| `padding1` | PSD FFT oversampling 4 → 1 | 580개 입력 기준 FFT 4096 → 1024. ACF FFT 길이는 유지 |
| `rate5` | FIR 뒤 10 Hz → 5 Hz | 필터도 새 출력률로 재설계. 단순 샘플 버리기 아님 |
| `top16` | 유효 칸 중 정규화 진폭 분산 상위 16개만 분석 | 10개 레코드마다 샘플링한 원시 진폭 통계. 호흡 점수가 아니므로 후보 손실 가능 |
| `stream` | 레코드마다 보간·FIR·다운샘플링, 축소 배열 보관 | 마지막 분석에서 전처리를 반복하지 않음. 연산을 앞당긴 효과와 총량을 구분 |

변경 누적 순서는 float → padding1 → rate5 → top16 → stream이다.
각 개별 변경은 baseline에서 하나만 바꾼다. 설정은 독립 옵션이므로
실험 결과가 좋지 않은 변경을 강제할 필요가 없다.

## 스트리밍 구현 범위

`csi_amp_stream_create/push/finish`는 **한 윈도우**의 증분 전처리 API다.
`push`는 들어온 레코드와 이전 레코드 사이의 100 Hz 격자를 채우고,
FIR 원형 버퍼에서 남길 출력 시점만 계산한다. 최종 축소 배열은
`csi_amp_process_raw`의 `prepared` 입력으로 사용한다.

현재는 고정 길이, `first_word_invalid=0`, 최대 100 ms 간격 입력만 지원한다.
조건 위반은 오류로 반환한다. 중복 타임스탬프는 마지막 샘플을 사용하고,
32비트 타임스탬프 래핑을 처리한다. 여러 윈도우를 계속 미는 캐시,
마스크가 바뀌는 입력, 수신·분석 태스크 간 동기화는 구현하지 않았다.
벤치마크에서는 고정 원시 입력을 패킷 단위로 재생한다.
`preprocess_us`는 전체 재생 전처리와 yield 시간, `max_push_us`는
단일 push의 최대 경과 시간이다. 이 시간이 수신 간격보다 크면 별도
스케줄링과 버퍼링 검증이 필요하다.

## 검증과 해석

기존 C/레퍼런스 테스트를 포함한 루트 테스트 25개가 통과했다.
기존 경로는 모든 필드를 byte 단위로 비교한다. 새 경로에는 float FFT의
NumPy 비교, 합성 주기 후보, 스트리밍의 지터·중복·타임스탬프 래핑,
잘못된 마스크·긴 간격·역행 거절 테스트를 추가했다.

녹화 21개의 처음 60초에 대해 각 변형을 비교했다. 호스트 시간은
컴퓨터에서 측정했으므로 ESP32 시간으로 환산하지 않는다. 수동 호흡 횟수는
선택에 사용하지 않았다. 채택 여부가 같다는 것은 정확도 검증이 아니다.

## 적용 정책

일반 RX 기본 설정에는 `CONFIG_CSI_RX_AMP_FLOAT_MATH=y`만 반영한다.
FFT oversampling은 4, 출력률은 10 Hz, 분석 대상은 전체 유효 칸을 유지한다.
호스트 `csi_amp_process`와 옵션을 지정하지 않은 raw API는 기존 수치 경로다.
`CONFIG_CSI_RX_AMP_BENCHMARK`는 측정 후 끈다. 일반 RX 동작은 기존처럼
부팅당 한 번 분석하는 시험 파이프라인이며, 지속적 매초 분석이 아니다.

- FFT padding 축소는 메뉴 설정으로 선택 가능하나 주파수 격자가 달라진다.
- 5 Hz와 top16은 실험에서만 사용한다. 정확도 향상으로 간주하지 않는다.
- 스트리밍 API는 재사용 가능한 실험 코드로 남기되 일반 수신 경로에 연결하지 않는다.
- 처리 태스크 스택은 선별 통계와 스트리밍 호출 여유를 위해 4096 → 8192 bytes로 늘렸다.

현재 로컬 `.git/info/exclude`가 `docs/`, `tests/`를 제외하고 있으므로
문서와 테스트는 디스크에는 존재하지만 일반 `git status`에 나타나지 않는다.
이 작업에서는 Git 제외 규칙을 바꾸거나 커밋하지 않았다.

### 메모리와 스트리밍 시간 해석

- stream 추가 상태: 376,412 bytes. 전처리 총 34.361초, 단일 push 최대 49.746 ms.
- combined_stream 추가 상태: 236,012 bytes. 전처리 총 15.881초, 단일 push 최대 41.291 ms.
- 원시 윈도우는 비교를 위해 계속 유지했다. 위 추가 상태는 원시 윈도우를 대체한 수치가 아니다.
- 실험 종료 후 힙 할당량은 각 변형 종료 때 같은 수준으로 복귀했다. 최소 여유 힙은 부팅 이후 누적 최솟값이므로 개별 변형의 독립 최대 사용량으로 해석하지 않는다.
- 스트리밍 구현은 PSRAM FIR 원형 버퍼 접근 등 비용이 추가되므로 일괄 처리보다 총시간이 증가했다. 보드에서 확정된 원인별 분해 측정은 하지 않았다.
- 100 Hz 입력은 10 ms 간격이다. 최악의 push가 그보다 길고 최종 분석도 수초 이상이므로 큐·태스크 재설계 없이 매초 결과를 보장할 수 없다.

가장 빠른 조합도 총 6.038초였고, 후보 손실이 큰 top16이 포함된다.
**1초 갱신 목표는 달성하지 못했다.** FFT뿐 아니라 보간·FIR·유효성 검사도
상당한 비용을 차지한다. 빠른 숫자만 보고 모든 변경을 기본으로 켜지 않는다.

## 일반 RX 모드 복귀 확인

측정 후 `/dev/ttyUSB0`에 벤치마크 OFF, 단정밀도 ON, oversampling=4인
펌웨어를 다시 플래시했다. 정상 부팅, 수신, 약 60초 윈도우 축적과
진폭 분석 완료까지 확인하고 모니터 포트를 닫았다.

- 실제 수신을 유지한 새 윈도우 분석: **38,286,384 us = 38.286초**.
- 결과: withheld, bin=53, PSD 3.369 bpm, ACF 45.453 bpm, reasons=0xa0.
- 분석 종료 때 queued=200. 수신이 유지되는 일반 모드에서는 분석 중 큐가
  포화하므로 연속 처리 문제는 여전히 남아 있다. 즉시 출력되는
  queue_drops=0은 최신 드롭이 없다는 증거가 아니다.
- 이 입력은 벤치마크와 다른 새 데이터이므로 후보 번호 차이를 수치 오차로
  해석하면 안 된다. 위 벤치마크의 직접 비교는 고정된 같은 입력끼리다.
- 복귀 로그와 설정은 `normal-uart.log`, `normal-build.log`,
  `normal-flash.log`, `normal-firmware.sha256`, `sdkconfig-normal`에 보관했다.
- 일반 앱 바이너리 0xdffe0 bytes, 1 MiB 앱 파티션 여유 0x20020 bytes.
