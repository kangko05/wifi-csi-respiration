# RX 진폭 고정소수점 전처리 실측 — 2026-09-22

## 범위와 결론

외부 서버 처리를 논의한 상태에서 사용자가 온보드 최적화 실험 계속 진행을 승인했다.
B0 Q15 FFT에 이어 진폭 계산·보간·FIR을 정수화한 B1 실험이다.
같은 60초 입력에서 float 기준 **38.057초 → 결합 경로 18.864초**,
약 50.4% 감소했다. 3초 내 분석·외부 전송 목표는 아직 달성하지 못했다.

증분 전처리(A), 연속 분석 스케줄링(C), 외부 전송은 이번에 구현하지 않았다.
추세 제거, Hann 적용, 스펙트럼 후처리, 점수 계산 등에는 실수 연산이 남는다.

## 구현

- `src/csi_utils.c`: int8 I/Q의 크기를 정수 제곱근으로 구하는 `csi_abs_q12`.
  소수부 12비트이며 전체 65,536개 입력 조합에서 오차 ≤ 0.5/4096 확인.
- `src/amplitude.c`: 절댓값 I/Q용 129×129 크기 표, Q15 보간 가중치,
  소수부 23비트 FIR 계수와 int64 누산을 추가했다. 보간 양 끝 크기를 재사용한다.
  FIR 이후 남길 샘플만 float로 변환하며 기존 계수 순서·마스크·시간 계약을 유지한다.
- 크기 표 66,564 bytes, 201탭 계수 804 bytes가 추가된다.
  기존 float 그리드는 같은 크기의 int32 그리드로 대체한다.
  표 생성은 호출당 수행하며 setup 시간에 포함된다. 부팅 시 캐시는 미구현이다.
- `include/csi_resp/amplitude.h`: 선택적 `fixed_preprocess`와 검증용 읽기 전용
  `observe_reduced` 콜백. 기존 prepared 경로와 동시 선택은 거부한다.
- `csi-rx/main/csi_process.c` 및 Kconfig: FFT 정수화와 전처리 정수화를 독립 비교.
  기존 double/float 경로를 보존하고 실험 옵션의 기본값은 꺼 둔다.

## 보드 실측

ESP32-C5 240 MHz, PSRAM 8 MiB/40 MHz, ESP-IDF 6.0.3, -O2.
5991개 레코드, 117개 칸, 입력 지문 `fa14b8d5`, 60초 윈도우,
축소 주파수 10 Hz, 580샘플, FFT oversampling 4를 모든 경우 유지했다.
수집 후 CSI 수신을 중단하고 같은 입력을 여섯 번 처리했다.

| 경로 | 분석 시간 | 준비·출력 포함 총시간 |
|---|---:|---:|
| float 기준 | 38.057 s | 38.171 s |
| Q15 FFT만 | 29.259 s | 29.364 s |
| 정수 전처리만 | 26.866 s | 26.971 s |
| 정수 전처리 + Q15 FFT | 18.864 s | 18.969 s |
| 결합 경로 반복 | 18.854 s | 18.959 s |
| float 기준 반복 | 38.043 s | 38.152 s |

마지막 float 결과는 최초 기준과 byte 동일했다. 결합 경로는 양자화 때문에
byte 동일하지 않으며, 두 반복의 표시 결과는 같았다.

| 단계 | float | 결합 경로 |
|---|---:|---:|
| 입력 유효성/공통 구간 | 2.471 s | 2.472 s |
| setup | 0.0001 s | 0.0507 s |
| 보간 | 9.838 s | 5.019 s |
| FIR | 6.927 s | 0.967 s |
| 추세 제거 | 0.780 s | 0.781 s |
| PSD | 8.752 s | 4.746 s |
| ACF | 7.689 s | 3.409 s |
| 점수 | 0.523 s | 0.447 s |

표에는 validate, yield, cleanup과 일부 출력 오버헤드가 생략되어 있다.
FIR은 약 7.2배 빨라졌다. 보간 개선에는 정수 연산과 크기 재사용이 함께 기여한다.
남은 큰 비용은 보간 5초와 PSD+ACF 8.2초이며, 추세 제거·점수만 정수화해서
3초를 달성할 수는 없다. 다음 후보는 전처리를 수신 시 분산·재사용하는 구조와
FFT 묶음 처리/작업 버퍼 배치다. 이들의 효과는 아직 실측하지 않았다.

모든 경로에서 후보 bin=96, PSD=3.076 bpm, 결과 보류 및 reasons=0x98이 유지됐다.
ACF는 float 40.895 → 결합 40.909 bpm이었다. 이는 호흡 정확도 검증이 아니다.
실험 중 내부 heap 최저 여유 16,260 bytes, PSRAM 최저 여유 4,629,016 bytes.
호출 후 할당량이 원래 값으로 돌아왔다. 연속 수신 중 메모리/큐 동작은 별도 검증해야 한다.

## 수치 검증

- 기존 녹화 21개 첫 60초에서 네 경로를 비교했다. 전부 성공했고 최종 채택 여부,
  최고/선택 칸, 칸별 채택 여부가 모두 같았다.
- 정수 전처리의 double 전처리 대비 파형 최대 절대 오차 0.000152588,
  녹화별 RMS 오차의 최대값 0.000037677이다.
- 정수 전처리만 적용: 후보 PSD 변화 0, 후보 ACF 최대 변화 0.0000362 bpm,
  칸별 점수 최대 변화 0.00000704.
- FFT까지 결합: 후보 PSD 변화 0, 후보 ACF 최대 변화 0.005306 bpm,
  칸별 점수 최대 변화 0.006688. B0에서 확인한 비선택 칸 피크 민감도는 여전히 한계다.
- 루트 unittest **36개 통과**. 전체 int8 범위, jitter/중복/wrap/마스크/gap,
  여러 축소율, 상수·주기 신호, 할당 실패/누수 정리까지 확인했다.
- full-range 무작위 입력의 결합 경로와 역행 timestamp를 UBSan으로 검사했고 통과했다.
  Python 하위 프로젝트 테스트는 이번 범위에서 재실행하지 않았다.

## 종료 상태

벤치마크를 끄고 기존 float 일반 모드(oversampling 4)로 재빌드·플래시했다.
복구 후 `window=98/6600 span=970ms`, 큐 누락/거부 0으로 수신 재개를 확인했다.
모니터를 종료해 포트를 해제했다. 현재 보드는 18.9초 실험 경로를 기본 실행하지 않는다.
이번 개선 코드는 선택 가능한 실험 경로로 남아 있으며 일반 모드는 기존 부팅당 1회 분석이다.
