# 온보드 보류 및 Python 복귀 인수인계 — 2026-09-22

> **최신 상태:** 전체 백업 후 Python 루트 복원을 완료했다. 현재 상태와 브랜치 복구 방법은 [Python 복귀 기록](python-return-20260922.md)을 따른다. 아래는 이전 이력이다.

## 최신 결정

사용자가 온보드 최적화를 여기서 보류하고 진행 상황을 저장한 뒤 Python으로
돌아가기로 했다. C 구현과 실험 산출물은 보존한다. 추가 정수화, 윈도우 축소
실측, 펌웨어 변경은 진행하지 않는다. 외부 서버 계산은 논의한 선택지이며
서버 장비·전송 방식·배포는 아직 확정하거나 구현하지 않았다.

이 결정은 과거 문서의 온디바이스 C 우선 방침보다 최신이다. 다음 작업의
출발점은 Python 처리 경로 점검이며, 과거 온보드 계획을 자동 재개하지 않는다.

## 완료한 온보드 작업

- ESP32-C5 RX의 콜백 → 200개 큐 → PSRAM 60초 원시 윈도우 → 진폭 분석 →
  별도 출력 모듈 구조를 연결했다. 위상·CIR 온보드 연결은 미구현이다.
- 원시 윈도우는 6600 × 540 = 3,564,000 bytes를 확보하며 약 100 Hz에서
  최근 약 6000개를 유지한다. PSRAM 8 MiB 사용을 부팅 로그로 확인했다.
- 필요할 때 칸별 작업 버퍼로 계산하도록 메모리를 줄이고, FFT 회전 계수
  캐시·float 경로·Q15 FFT·정수 진폭/보간/FIR 경로를 비교했다.
- B1 정수 전처리는 Q12 진폭, Q15 보간 가중치, Q23 FIR 계수와 int64 누산이다.
  전체 파이프라인이 고정소수점인 것은 아니다.

## 최종 실측 결과

같은 60초 입력 5991개, 117개 서브캐리어, 축소율 10 Hz, 출력 580샘플,
FFT oversampling 4. ESP32-C5 240 MHz, PSRAM 40 MHz, -O2.

| B1 비교 경로 | 분석 시간 |
|---|---:|
| float 기준 | 38.057초 |
| Q15 FFT만 | 29.259초 |
| 정수 전처리만 | 26.866초 |
| 정수 전처리 + Q15 FFT | **18.864초** |
| 결합 경로 반복 | 18.854초 |
| float 기준 반복 | 38.043초 |

결합 경로의 준비·출력 포함 총시간은 18.969초다. 최종 주요 비용은
유효 구간 검사 2.472초, 보간 5.019초, FIR 0.967초, 추세 제거 0.781초,
PSD 4.746초, ACF 3.409초다.

이 비교는 수집 후 수신을 중단한 고정 입력 벤치마크다. 분석 중 계속 수신하거나
외부 전송하는 비용은 검증하지 않았다. 목표인 최신 윈도우 분석과 결과 전달
합계 3초는 미달이다. 30초·20초 윈도우의 시간은 **미측정**이며 대화 중
5~6초 언급은 추정일 뿐이다. 20초 적용 시 FIR 경계 제거와 최소 유효 길이
조건도 함께 검토해야 한다.

## 수치 검증과 한계

- 기존 녹화 21개 첫 60초에서 최종 채택 여부·최고/선택 칸·칸별 채택 여부 동일.
- 정수 전처리의 double 대비 파형 최대 절대 오차 0.000152588.
- 결합 경로의 float 대비 후보 PSD 차이 0, 후보 ACF 최대 차이 0.005306 bpm.
  일부 비선택 칸의 피크는 Q15 FFT에 민감했으므로 완전 동등한 결과는 아니다.
- 루트 테스트 36개와 UBSan 검사 통과. 실제 호흡 정확도 검증과 구분한다.
- Python 하위 테스트는 이번 최적화에서 재실행하지 않았다. 기존 기록의
  입력 검증 실패 14건은 해결되었다고 간주하지 않는다.
- 기존 위상/CIR 평가에는 빈 방 오채택 문제가 남아 있다. 서버로 옮기는 것만으로
  호흡 유무 판정이나 최근 호흡 중단에 대한 반응 지연이 해결되지는 않는다.

## 보드 및 저장소 종료 상태

최종 실측 후 벤치마크를 끄고 **기존 float 일반 모드**로 복구했다.
최종 확인 로그는 `window=98/6600 span=970ms`, queue_drops/rejected=0이다.
일반 모드는 부팅당 분석 1회이며 18.9초 실험 경로가 기본 활성화된 상태가 아니다.
마지막 사용 포트는 RX `/dev/ttyUSB0`, 모니터는 종료했다. 이번 문서 저장에서는
포트를 열거나 플래시하지 않았다. 다음 하드웨어 작업 때 준비 상태를 확인한다.

원본 data/vendor를 보존했고 커밋·푸시하지 않았다. `docs/`, `tests/`는 로컬
exclude로 Git 상태에 안 나타날 수 있으므로 추후 공유할 때 포함 여부를 확인한다.

## Python에서 이어갈 순서

1. `python/AGENTS.md`, `python/PROGRESS.md`와 기존 실행 스크립트를 읽고
   현재 사용 가능한 진폭·위상·CIR 경로 및 작성 중인 전처리 상태를 구분한다.
   `scripts/run_c_amplitude.py`는 C 실행 래퍼이므로 순수 Python 처리와 구분한다.
2. 기존 녹화와 보존된 결과로 Python 기준선을 재현한다. 기존 입력 검증 실패
   14건을 확인하고 필요한 수정 범위를 정한다. vendor나 원본 캡처는 수정하지 않는다.
3. 실행할 PC/서버가 정해지면 읽기·전처리·분석을 나눠 시간을 잰다. 60초 윈도우와
   3초 갱신을 출발점으로 삼되, 감지 지연/정확도와 계산 지연을 따로 평가한다.
4. 온라인 연결 시 원시 I/Q, 순번·타임스탬프, 유효성·CSI 길이 등 필요한
   메타데이터를 유지하는 입력 형식을 정한다. 현재 RX 출력이 기존 Python 수집기와
   호환되는지 먼저 확인하고, 큐 넘침·누락·연결 중단을 숨기지 않는다.

위 순서는 다음 작업 제안이다. 이번에는 Python 코드 변경이나 서버 연결을 시작하지 않았다.
온보드 재개 후보인 전처리 재사용, FFT 묶음 처리, 내부 RAM 버퍼 배치,
30/20초 윈도우 비교는 미구현·미측정 항목으로 남긴다.
